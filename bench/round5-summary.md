# 第五轮：改写发散档措辞，去掉“刻意反直觉”（2026-11-03）

## 改动（commit `0abdd9e`）

旧规则要求“至少一个常规答案不会包含的选项”，容易逼出刻意的反常识。新规则：

- 给 3–5 个**做法不同**的方向（少做 / 换做法 / 消掉需求），不是同一答案的变体；
- 先检查前提：**显然的答案就直接说并停止**，不为显得有创意而硬造选项；
- 每个方向说明为什么可行、代价是什么；**无法说明理由的删掉**；
- 仅措辞不同就保留更好的那个；区分事实与推测。

## 任务 1：创意任务（同题，3 次）

| 文件 | 方向 | 是否刻意“反常规” | 成本/证伪 |
|---|---|---|---|
| ideation-1 | 模式存活率实验 / 忠实档改成“抽取式契约” / 发散档改成候选池 | 无（没有硬凑的反直觉段） | 有 |
| ideation-2 | 提示词消融 / 风格改由 tool schema 承载 / 200 行模块的编辑纪律 | 无 | 有 |
| ideation-3 | 删开关 dogfooding / 存量产物离线指标 / 规则行级消融 | 无 | 有 |

对比第四轮：4B 的三份都有明确标注的“非常规/非主流”方向（工具门控、时间线、拓扑化），那是旧规则逼出来的形态。这一轮没有这种段落，但**方向依然互不相同**。

## 任务 2：明显答案（“10 行脚本要不要拆 3 个模块”，2 次）

- obvious-1：先给结论「不要拆」，再给替代改进（加固 shell 选项、同文件函数化、外置配置、直接用 mogrify）。
- obvious-2：先给结论「不要拆」，再给拆分阈值（第二个调用方、超过一屏、需要单测纯函数等）和 5 个替代方向。

两次都没有为了“发散”而制造“应该拆”的理由——旧规则下这是最可能出现的刻意输出。但“显然就停”没有被严格执行：两次都在结论后继续给了替代方案。

## 结论

- 措辞改动**有效**：去掉了刻意感，保留了方向多样性；
- “显然就停”偏软：模型会把“不要拆，但可以这样改进”一起给出。这不是坏事，但和字面规则有出入；
- 输出仍然偏长（69–84 行）——这是模型风格，不是档位差异。
