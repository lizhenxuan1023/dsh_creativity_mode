# 创意模式插件：三个下一步实验方向

先对齐现状，它决定了哪些方向值得花时间：

- 三档风格目前只作用在**措辞层**——切换时注入一条 user 角色 notice（balanced ≈ 50 token，divergent/faithful ≈ 250 token），系统提示词逐字节不变。模型收到的规则多了，但推理路径、采样数、工具调用都没变。
- 因此「档位有没有用」和「提示词写得对不对」是同一个问题：都只能靠对比输出回答，目前缺这个对比。
- 用户的两个真实痛点（ROADMAP）：不知道 index.js 里的提示词该怎么调；希望发散档真的发散，而不是同一段话换个说法。

---

## 方向一：档位对照评测（建议先做，另两个方向的地基）

**做法**
固定 10–15 个任务，整理类、头脑风暴类、普通改代码类各占一部分。每个任务锁死同一份上下文与提示词，只换档位；每档每任务跑 2–3 次，用来区分「档位差异」和「单次抖动」。评分两把尺子：

- 可机器判定的：faithful 看有没有漏细节、有没有加原文没有的结论、矛盾是否标注；divergent 看方向数量与两两相似度（区分「真不同」和「同义改写」）；balanced 看有没有多余的仪式感。
- 盲评：洗掉档位标签，人工或另一模型两两选优。

**成本**
- 一次性搭 harness：0.5–1 人日（会话脚本、输出落盘、相似度与覆盖率脚本）。
- 每次跑：12 任务 × 3 档 × 3 次 = 108 次调用，量级约等于一次长会话；串行排队慢，并发可压到几十分钟。
- 维护面：评测集要防止被针对性优化；出题和改提示词的人尽量分开。

**收益**
- 把「感觉不对」变成数字：能直接回答 faithful 到底有没有少总结、divergent 给的方向是不是真不同。
- 是方向二的前置——没有基线，「新提示词更好」无法判断。
- 留下一套可复跑的回归测试，以后改 `RULES` 就是跑一遍的事。

**风险与止损**
任务太少结论会不稳。若同一档的两次差异 ≈ 不同档之间的差异，说明当前 notice 太弱——这不是失败，这是最有价值的结论，直接喂给方向二。

---

## 方向二：notice 变体的单变量迭代（解决「不知道怎么调提示词」）

**做法**
把 `RULES` 从硬编码常量抽成可切换的变体集，例如 faithful 三个变体：只禁总结 / 禁总结 + 强制 open questions / 禁总结 + 逐条引用。用方向一的评测当打分器，一次只改一条规则。第二轮可以让模型根据失败样例自己提改写，人来选，但同样要过评测。

**成本**
- 改造：`RULES` 移到数据文件，加一个 variant 维度的投影，0.5–1 人日。注意变体不能进系统提示词——每次变化会给 in-history 模型追加一整份约 1.7k token 的副本。
- 每轮评测：与方向一同量级；人工挑变体是主要时间成本，每轮 1–2 小时。
- 维护面：变体集容易膨胀，需设上限（每档最多 3 个），否则没人清楚线上跑的是哪个。

**收益**
- 提示词迭代从「读一遍凭感觉改」变成「改一条、跑一遍、看差异」。
- 能定位到哪条规则真正在起作用：很可能是最后一条和最强的那句限制在驱动行为，前面的说明性条目可以删——顺手把 notice token 降下来。

**风险与止损**
十几个任务上反复调参会过拟合，留 3–5 个任务不参与调参，只在最后验收。若两轮后差距仍在噪声内，停手：瓶颈不在措辞，转方向三。

---

## 方向三：把「发散」从措辞层下沉到执行层（多路采样）

**做法**
divergent 档下对同一问题并发跑 N 路（不同开头/温度，或 3 路子 agent），再做挑选或合并。合并规则必须显式：按方向去重，冲突处保留并标注，不揉成一段。

**成本**
- 执行与合并逻辑：1–2 人日，还要处理失败分支、超时、合并冲突。
- 运行成本：N 倍 token 与延迟，N=3 是最低可用值；并发失败会拉长尾。
- 维护面最大：合并质量本身也要评测，等于给方向一再加一类任务。

**收益**
- 这是唯一能真正抬高「方向多样性」上限的做法。单次调用里让模型更发散有天花板，多路采样换的是采样空间，不是形容词。
- 顺带产出可复用的编排与合并管道，以后 Ultra 之类的重档位可以直接复用。

**风险与止损**
先做 N=3、单任务的离线原型，与单路 divergent 盲评对比。若盲评选不出差别，收益撑不起 N 倍成本，就不进产品。

---

## 对比与顺序

| 方向 | 主要成本 | 主要收益 | 失败时学到什么 |
| --- | --- | --- | --- |
| 一、对照评测 | 0.5–1 人日 + 每轮 108 次调用 | 唯一的可信基线，可复跑回归 | 档位差异是否存在（本身就是答案） |
| 二、变体迭代 | 0.5–1 人日改造 + 每轮评测与人工挑选 | 提示词可按证据改，token 可降 | 瓶颈不在措辞 |
| 三、多路采样 | 1–2 人日 + N 倍运行成本 | 多样性真上限，可复用编排 | 成本换不来可感知的差异 |

**建议顺序：一 → 二 →（可选）三。** 方向一是唯一能让另外两个结论可信的东西，且成本最低；方向二在有方向一时是几小时的活，没有时是猜；方向三最贵，而它的价值判断恰好依赖方向一的盲评。

**如果只做一件事**：做方向一，并且先只测 faithful 档——用户对它的定义最清楚（「减少自己的判断和总结」可判定），8 个任务就足以看出方向。

**附带说明**：Ultra 模式（「token 预算无限」提示词）不算实验方向，属于零成本试一把的调参项；但它的效果同样要过方向一，否则只是自我安慰。
