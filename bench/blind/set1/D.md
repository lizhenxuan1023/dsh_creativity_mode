# 创意模式插件：三个下一步实验方向

现状（已实现）：三档位 `divergent / balanced / faithful`，靠 `agent/pre-step` 往对话里补一条
`creativity-mode` notice（balanced ≈ 50 token，divergent / faithful ≈ 250 token）来生效，不复制系统提示词。
核心赌注是「用户级 notice 足够改变行为」，但这笔赌注还没被验证过。

下面三个方向分别咬不同的未知：**行为到底变没变**（测量）、**哪句提示词在干活**（拆解）、
**风格该不该由形容词承载**（重构）。三者不重复，可以并行，也可以只挑一个。

---

## 方向 1：同题三档盲测台——把「感觉不一样」变成一张分数表

**要回答的问题**：切档之后产出真的不同、且更好吗？在哪些任务上反而更差？

**做法**
- 选 10 个任务，覆盖 4 类：开放性构思、资料整理、代码/配置修改、含混需求澄清。
- 每档跑 3 个种子（同上下文、同提示词，只换档位），共 90 次。
- 输出统一去掉档位痕迹、打乱顺序，再用另一模型按 4 个维度盲评：新意、覆盖度、忠于原文、编辑纪律；
  同时加机械判据（不靠模型打分）：divergent 是否真的给出 ≥3 个互不相同的方向、faithful 是否出现了原文没有的措辞
  （对原文做 diff，任何新增断言都算越界）。
- 存成基线表，之后每次改提示词都重跑同一张表。

**成本**（估算）
- token：约 90 次 × 3–6k ≈ 0.3–0.5M，一次性；judge 另算约 1/3。
- 工程量：2–4 小时（harness 跑批 + 打乱 + 汇总表），没有新 Host 代码，纯外部脚本。
- 隐性成本：judge 自身有偏好（偏爱长答案），机械判据只能覆盖一部分；90 个样本统计力有限，只能看大方向。

**收益**
- 第一次拿到「档位 × 任务类型」的交叉表，能直接回答「什么时候不该发散」——现在这是空白。
- 这张表变成回归基线：以后改 notice、加 Ultra 档、调合并策略，都有一个可以对照的东西。
- 顺带验证 faithful 的边界：如果 diff 显示它仍会加总结，说明「不加判断」这条指令根本没被遵守，
  这比任何主观评价都硬。

【推测】我预计 faithful 只在资料整理类明显赢，divergent 在代码修改类会被扣「编辑纪律」分，
但两者在含混需求澄清上可能都赢 balanced——如果真是这样，档位就不该按「性格」划分，而该按任务划分。

## 方向 2：把 notice 当可编译产物——逐句消融 + 变异爬坡

**要回答的问题**：那 250 token 里，哪几句真在改变行为？有没有句子在帮倒忙？

**做法**
- 把 divergent 的 notice 拆成原子子句（求新求广 / 3–5 个方向 / 质疑前提 / 至少一个非显然选项 /
  改文件时切编辑纪律 / 其余的措辞）。每次去掉一句，跑固定的 5 题探针，看分数掉多少。
- 掉 0 的子句 = 死重，删。掉分的子句 = 核心，留下并考虑加强。负分的子句 = 反效果，重点看。
- 然后进入变异循环：每代生成 5–8 个候选（改写、合并、缩短），用同一探针打分，
  按「分数 / 长度」的 Pareto 前沿保留（不只看分，也看 token，因为每次切换都要付这笔钱）。
- 判官用方向 1 的机械判据 + 少量人工抽查，避免自评自嗨。

**成本**（估算）
- 每代约 (子句数+1)×5 ≈ 40–60 次运行，几代下来 0.1–0.2M token，比方向 1 便宜。
- 工程量：1 天左右，主要花在「候选怎么自动生成」和「分数噪声怎么压」上。
- 真风险：对探针过拟合。5 题上赢的措辞可能只是碰巧；必须留一组不参与优化的 holdout 题。

**收益**
- 直接砍掉无效子句，notice 从 250 token 降到 120 以内是可达的：每次切换省一半，
  且指令越短越不容易被系统规则稀释（README 自己承认 notice 压不住系统级规则）。
- 能定位「帮倒忙」的句子。比如「3–5 个方向」可能让模型对一个只有一句话的问题也硬凑五条，
  这种代价现在完全没被观测到。
- 顺手把 ROADMAP 里「提示词怎么自我迭代」变成一个可重复的循环，而不是凭感觉改。

【推测】我猜「至少一个非显然选项」和「质疑前提」是真正拉开差异的两句，
而「3–5 个方向」是数量约束、最容易诱发灌水——但这是猜的，消融会给出答案。

## 方向 3（非主流）：风格不靠形容词，靠拓扑——把档位做成「调度器」

**要回答的问题**：如果「发散」不是一句嘱咐，而是一次并行采样，会不会更可靠？

**做法**
- 重新定义三档为三种执行拓扑，而不是三种语气：
  - **divergent**：同一问题上并发跑 3 个子 agent，各自用不同切入框架（用户视角 / 反例优先 / 约束反转），
    主 agent 只做去重和合并，不重新生成。
  - **faithful**：走确定性管线（切块 → 逐块引用 → 拼装），能不做生成的地方就不做，
    把「忠于原文」变成结构保证而不是自觉。
  - **balanced**：单次直答，即现状。
- 先不写代码验证：手工开 3 个子 agent 跑 5 个题，和单次发散对比，看「方向数」和「方向间差异度」
  是否真的提升（用嵌入距离或人工判重）。

**成本**（估算）
- token / 延迟：发散档直接 ×3，交互式场景下这是能明显感知的卡顿；faithful 反而可能更省。
- 工程量：真正落地要在 Host 侧接子 agent 服务、处理部分失败、把 fan-out 渲染进 UI，约 2–3 天，
  比前两个方向重得多，且会让「档位」从纯提示词概念变成有执行语义的东西。
- 兼容成本：并行分支的上下文如何回注主对话、压缩时怎么折叠，都要重新设计。

**收益**
- 绕开最大的不确定性：README 明确说 notice 属于用户级指令、压不住系统级规则。
  拓扑不依赖模型「听话」，广度由构造保证——三个分支必然给出三份不同的东西。
- 档位的含义变得可测量：发散 = 3× 预算，忠实 = 0 生成，平衡 = 1×。
  「预算」比「风格」更适合当开关，也更容易向用户解释。
- 如果成立，它会推翻现在的实现假设（notice 注入），把插件从「提示词注入器」升级成「执行策略器」——
  这是三个方向里唯一可能改变产品形态的。

【推测】这条路在构思类任务上大概率赢，但在「改一个配置」这种小任务上会显得荒谬地重；
更可能的归宿是它不替代 notice，而是作为 divergent 档的一个子选项（«深挖» 开关）。

## 怎么选

| 方向 | 一次性成本 | 主要收益 | 何时做 |
| --- | --- | --- | --- |
| 1 盲测台 | 0.3–0.5M token + 半天 | 知道档位何时有害；建立回归基线 | 先做，它是另两个的度量基础 |
| 2 消融/爬坡 | 0.1–0.2M token + 1 天 | notice 减半，找出帮倒忙的句子 | 有基线之后立刻做，边际收益最高 |
| 3 拓扑化 | 2–3 天 + 3× 运行时 | 绕开「听不听话」，改变产品形态 | 前两个证明「形容词不够用」之后再投入 |

如果只做一件事：做方向 2。它最便宜、最直接动到现在唯一真正的实现细节（那 250 token），
而且不管结果如何都能立刻上线一版更短的 notice。

一个 30 分钟的先行实验（三个方向都用得上）：同一会话里连续切档 0 / 1 / 5 / 20 次，
测上下文增长与输出质量漂移。它能提前告诉你「频繁切换」这件事本身值不值得担心——
现在所有成本讨论都默认切换是免费的，这个默认还没被验证过。
