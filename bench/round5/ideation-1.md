# 创意模式插件：三个下一步实验方向

先把框架摆正：这个插件已经解决了「怎么把风格指令便宜地送进上下文」——notice 约 250 token，而改系统提示词会追加约 1.7k token 的副本（README 事实）。但它还没回答三个未知：

1. **机制**：长会话、压缩、fork/resume 之后，档位是否真的还在生效？
2. **内容**：`faithful` 到底该定义成什么？ROADMAP 10-31 里「strict 偏离本意」至今没有答案。
3. **方法**：`divergent` 的多样性只能靠提示词吗？同一模型、同一上下文，换措辞很容易假装成「不同」。

三个方向分别打这三个未知，成本递增，建议按 1 → 2 → 3 做，不要并行。

| 方向 | 打的未知 | 成本（估算） | 收益 | 止损线 |
| --- | --- | --- | --- | --- |
| 一、存活率实验 | 机制是否静默失效 | 0.5–1 人日，几乎不改代码 | 一个可回归的「模式存活率」数字 | 任一探针失败，先修再谈功能 |
| 二、faithful 改为抽取式 | 「别总结」能否由格式保证 | 1–2 人日，约 100–150 行 | 把说不清的风格变成可验收的格式 | 零添加不达标就退回契约版 |
| 三、发散候选池 | 多样性该来自采样还是提示词 | 3 倍生成 token + 100–150 行 | 真正独立的方向，而非同义改写 | 独立簇数不提升就删除 |

---

## 方向一：模式存活率实验（先证明它没有静默失效）

**假设**：README 的三条承诺在真实长会话里成立——切换写入日志、重启/恢复/fork 保留、压缩后自动补发 notice。

**做法**：开一个一次性会话（不要污染常用会话），脚本化 25–30 轮：

- 前 17 轮普通问答，把上下文推过压缩阈值；
- 第 18 轮切到 `faithful`，等一步让它生效；
- 第 20 轮塞入一份约 3k 字的原始材料，要求「整理」；检查输出有没有总结句、评价句、顺序重排；
- 探针 A：同材料在全新会话直接 `faithful`，对比两次输出的「签名」差异——差异就是存活率损失；
- 探针 B：切档后立刻 fork，子会话是否继承当前档位；
- 探针 C：resume 后不切档，直接问一个只有 `divergent` 才会给出 3 个以上方向的任务；
- 顺带用 usage 日志核对每次切换的真实 token 增量，验证 250 这个数字。

**成本**：0.5–1 人日；一个脚本 + 一份材料；不改插件（最多加一个只读的 `/creativity debug` 命令）。token 量级几十万，费用可忽略。

**收益**：这类失败没有报错，用户只会觉得「今天模型不听话」，所以它比任何新功能都优先。跑完顺带得到一套回归用例，之后每次改投影/notice 逻辑都能复跑。

**判据**：三个探针全过 → 进入方向二；任一失败 → 先修投影或补发逻辑（估算 <100 行），修完重跑，再谈新功能。

---

## 方向二：`faithful` 不该靠「别总结」，而该靠「没法总结」

**假设**：违反「不总结」的根源不是指令不够强，而是让模型自由写散文——只要允许它组织语言，它就一定会做判断和归并。换成抽取式表示后，「零添加」由构造保证，而不是靠模型自觉。

**做法**：同一批 10 份材料（新闻、会议记录、多来源笔记各若干），三臂对照：

- **A 现状**：现在的 `faithful` 提示词；
- **B 契约版**：前置 4 条可检查约束（段落覆盖、顺序一致、无「因此/说明/总体来看」类推论句、原文矛盾标 `[as written]`），输出前同轮自检一次；
- **C 抽取版**：源材料按段落编号，模型只输出 `[段号] + 原文摘句 + 可选结构标签`，不允许连接词和改写，最后可加一份「只有标题的导航」。

评三个指标：要点覆盖率、顺序逆序对、零添加违反率（人工盲评或独立 judge）。

**成本**：B 每轮多 10–20% 输出 token，无额外延迟；C 需要编号/渲染的小工具和输出模板，约 100–150 行，但 token 往往更少（引用短于改写），主要代价是可读性下降。评测本身 1–2 人日。

**收益**：如果 C 的零添加接近 100%，那 `faithful` 就从「风格」变成「格式」，用户可按需选可读版（B）或可审计版（C）。这也直接回答 ROADMAP 里的困惑：所谓 strict，其实是「可读的整理」和「可核对的摘录」两种需求被塞进了一个档位。

**判据**（阈值为预设，可调）：B 的违反率 ≤ A 的 50% 就用 B；否则看 C 是否 ≤ A 的 20% 且可读性评分不低于 A 的 80%；两者都不达标，说明「忠实」更适合做成独立工具（结构化输入输出），而不是风格档。

## 方向三：发散档改为「候选池」——多样性从提示词移到采样

**假设**：现在 `divergent` 靠一段约 250 token 的指令要求「3–5 个真正不同的方向」，但同一模型同一上下文里，所谓不同经常只是换措辞。3 路各带不同约束的并行采样，去重后的独立方向数会显著高于单路。

**做法**：

- 只在用户显式要「深度发散」时触发，默认不开，避免 3 倍成本常态化；
- 3 个子 agent 各给一种 framing：反例优先（先找会让方案失败的前提）、跨域类比（从别的行业借结构）、极端约束（预算/时间砍到 1/10 会怎样）；
- 父 agent 只做去重、合并、标注来源，不重写；
- 度量：固定产出 5 条，按「是否共享同一核心机制」聚类，比较独立簇数，同时记录 token 和墙钟时间。

**成本**：3 倍生成 token（并行，墙钟约 1.3–1.5 倍）；编排与失败处理约 100–150 行；必须设单次 token 上限，否则一次探索可能烧掉整轮预算。这是三个方向里唯一会改变默认体验成本的。

**收益**：多样性来自采样而不是形容词，这是唯一能绕开「同一段话换个说法」的机制；候选集还能直接作为后续选择的输入。若实验失败，也说明该模型的发散瓶颈不在采样数，可以永久省下这笔成本。

**判据**：独立簇数中位数提升 ≥1，且单位成本产出的「新方向」不少于单路 → 保留为可选档；否则删除，不进默认路径。

---

## 排序，以及现在不建议做的

**顺序**：一 → 二 → 三。方向一是信任前提，否则后两个的结论都可能是噪声；方向二直接回应用户自己还没解决的 strict 问题；方向三最贵，只在前两个证明「模式确实在起作用」后才值得投。

**不建议现在做**（判断，非事实）：ROADMAP 10-30 #3 的 Ultra 模式——「token 预算无限」这类提示词，更容易换来篇幅而不是质量，也把「更多思考」和「更长输出」混为一谈。真要做，先把它当成方向一里的一个变量来测，而不是直接加档。同理，按任务类型自动推断档位也先放一放：模式本身是否有效还没验证，自动化只会放大不确定性。
