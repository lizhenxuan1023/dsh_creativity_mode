# 10 行图片转 webp 脚本，要不要拆成 3 个模块？

## 直接结论

**不拆。** 对 10 行、单一职责、没有第二个调用方的脚本，"拆成 3 个模块"是负收益：
它把一份可以一眼读完的东西，换成三份需要跳转、需要维护接口契约的东西。
"可维护性"不是文件数量的函数，而是**读完全部代码所需的时间 + 改动时需要同步修改的点数**。这个脚本两项都接近下限。

拆分后必然新增的成本（不是猜测，是结构性的）：

- 3 个文件之间的 import 路径、执行顺序、参数传递、退出码约定；
- 每个模块的"边界"要靠命名和注释维持，10 行代码里这些注释的占比会超过逻辑本身；
- 单文件能 `bash script.sh` 直接跑，拆完要么留一个入口脚本（实际变成 4 个文件），要么要装包/改 PATH；
- 出 bug 时要跨文件追一条数据流，而原本滚轮都不用动。

只有当**下面任一条件成立**时，拆分才开始有正的边际收益（这是经验阈值，不是定律）：

1. 脚本涨到需要滚动一屏才能读完（约 50 行以上）；
2. 出现第二种用法：被别的脚本 `source`、被 CI 调用、要加 `--watch` 或并发；
3. 逻辑分叉：要处理"已存在 webp 跳过"、EXIF 方向、尺寸/质量策略；
4. 需要单元测试某个纯函数，而它现在埋在主流程里；
5. 已经因为改动它出过一次事故——那说明缺的是测试，不是文件划分。

## 五个方向（不是同一种答案的措辞变体）

### 方向 A：什么都不拆，只把这 10 行收紧
保留单文件，顺手让它"可读且安全"：`set -euo pipefail`、参数校验、`usage`、对已存在的 `.webp` 跳过、`cwebp -q 82` 一次成型。
**为什么可行**：维护痛点的真实来源通常是边界情况（空格文件名、失败继续、重复执行），而不是文件布局。这些修完，10 行还是 10 行出头。
**代价**：几乎为零；只是要压住"顺手重构"的冲动。

### 方向 B：拆成两个文件，而不是三个模块
一个薄入口（解析参数、遍历、报告），一个库文件（`to_webp()` 单个文件的转换 + 跳过判断）。
**为什么可行**：这是"可复用"诉求的最小满足——将来别的脚本要转图，`source` 库文件即可；入口不被污染。
**代价**：多一个文件、多一条 `source` 的路径假设；只有在**真的出现第二个调用方**时才值得。

### 方向 C：不维护这段代码，让它消失
用现成工具替代：`find . -name '*.png' -exec cwebp -q 82 {} -o {}.webp \;`，或 `mogrify -format webp`，或 `parallel`+`cwebp`。
**为什么可行**：脚本 100% 的工作是"循环 + 调一个已经很成熟的转码器"，这部分本来就是别人维护的。
**代价**：多一个外部依赖，跨平台一致性变差（macOS 上 ImageMagick 的 webp 支持常要额外装）；但需维护的代码从 10 行变成 0 行。

### 方向 D：换载体而不是拆模块——做成 `justfile` / `Makefile` 任务
把"转图"变成 `just webp` 或 `make webp`，参数写进任务定义。
**为什么可行**："可维护性"在这个规模上常被误诊，真实诉求往往是**可发现、可重复执行、不用记参数**。Make/just 的增量规则天然给你"已存在就跳过"。
**代价**：多一层工具依赖；用 make 表达"遍历目录"会比 shell 别扭。

### 方向 E：如果目标是团队可维护，投资测试和 README，而不是文件划分
用一个 `bats` 测试（3 条：正常转换、忽略非图片、文件名带空格）+ 一段 5 行 README 说明质量和输出位置。
**为什么可行**：测试锁住的是**行为**，重排文件锁住的是**观感**；前者能在未来改动中救你，后者不能。10 行脚本恰恰是加测试成本最低的时候。
**代价**：多一个测试文件和 CI 里的一条命令；对一次性脚本是过度投入。

## 如果一定要拆（比如团队规范强制）

按**数据流**切，而不是按"文件/转换/报告"这种听起来整齐的词切：

- `list_images(dir)` → 输出路径列表
- `convert_one(src, dst, quality)` → 幂等，已存在则返回 0 并标记 skipped
- `main` → 串起来 + 汇总统计

三个函数留在**同一个文件**里也能获得 90% 的收益。等到某个函数被第二个脚本使用时，再把那个函数搬出去——**按需抽出，而不是预先切分**。

## 一句话

10 行单职责脚本不该为"可维护性"拆成 3 个模块；先把它写对（幂等、引号、错误处理），再考虑让它消失，把"文件划分"留到出现第二个调用方或第二种用法的那天。
